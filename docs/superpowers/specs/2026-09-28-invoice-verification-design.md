# 多格式纸质发票智能核对与查重系统设计

## 1. 目标

构建一个多用户全栈 Web 系统，接收图片和 PDF 形式的纸质票据扫描件，通过百度智能云 Paddle OCR 完成结构化识别，并自动执行字段核验、异常提示和跨格式查重。风险票据必须经过人工复核，只有已通过票据才能进入台账或导出给 ERP。

首版验收目标：

- 覆盖至少 8 类常见票据。
- 脱敏基准样本的结构化字段识别准确率不低于 98%。
- 确定重复票拦截率达到 100%。
- 已标注异常样本的异常召回率不低于 95%。
- 支持 Excel/CSV 台账导出和 ERP 集成接口。

## 2. 范围

### 2.1 首版包含

- 用户注册、登录和数据隔离。
- 用户自行录入、测试和更新百度智能云 OCR API Key 与 Secret Key。
- 单张或批量上传 JPG、JPEG、PNG、PDF；每批最多 100 个文件，单文件最多 20 MiB，单个 PDF 最多 20 页。
- 增值税专票、增值税普票、电子发票、火车票、机票行程单、出租车票、定额发票、海关缴款书识别。
- 原票预览、OCR 字段展示、置信度提示和人工修正。
- 字段完整性、格式、金额关系和低置信度核验。
- 确定重复拦截与疑似重复提示。
- 发票台账、筛选、批次处理、CSV/Excel 导出。
- 面向 ERP 的查询和推送接口。
- 操作审计。

### 2.2 首版不包含

- 发票真伪税务联网查验。
- 自动控制物理扫描仪。
- 移动端原生应用。
- 财务审批流、报销流程和会计凭证生成。
- 微服务、消息队列、Redis 或独立对象存储集群。

## 3. 技术架构

采用 Vue 3、TypeScript、Vite 构建前端，Spring Boot 构建模块化单体后端，PostgreSQL 保存业务数据。前后端通过 REST API 通信，耗时任务状态通过 SSE 推送；SSE 不可用时前端降级为轮询。

后端按职责分为以下模块：

- `identity`：用户注册、登录、会话和访问控制。
- `credential`：OCR 凭据加密、测试、更新和掩码状态。
- `ingestion`：文件校验、批次创建、文件哈希和任务编排。
- `ocr`：百度智能云令牌管理、OCR 请求、重试和响应映射。
- `normalization`：不同票种字段映射到统一发票模型。
- `verification`：必填字段、格式、日期和金额关系规则。
- `deduplication`：确定重复键、疑似重复评分和并发拦截。
- `ledger`：台账查询、统计和导出。
- `integration`：ERP 查询与推送接口。
- `audit`：关键操作记录。

原始文件首版保存在可配置的服务端目录，数据库只保存受控文件标识、哈希和元数据。文件下载和预览必须经过后端鉴权，不直接暴露静态目录。

## 4. 核心业务流程

1. 用户登录并在设置页录入百度智能云 OCR 凭据。
2. 后端验证凭据有效性，使用服务端主密钥加密后保存。
3. 用户单张或批量上传票据；系统校验扩展名、MIME、大小和文件内容。
4. 系统计算 SHA-256，创建批次、原始文件和处理任务。
5. OCR 适配器调用百度智能云 API，保存原始结果、字段值和置信度。
6. 归一化模块识别票种，并把日期、金额、代码、号码及交易主体映射到统一模型。
7. 核验引擎执行必填字段、格式、日期、金额和置信度规则。
8. 查重引擎执行确定重复和疑似重复检查。
9. 系统把票据标记为“已通过”“待复核”“已拦截”或“处理失败”。
10. 用户在三栏核对台中对照原票修正字段。修正后重新执行核验和查重。
11. 只有“已通过”票据可写入台账、导出或推送 ERP。

## 5. 核验与查重

### 5.1 核验规则

- 检查各票种的关键字段是否存在。
- 校验发票代码、号码、税号、日期和金额格式。
- 校验价税合计与不含税金额、税额之间的关系，并允许货币舍入误差。
- 检查日期是否明显超出合理范围。
- 关键字段置信度低于可配置阈值时转入人工复核。
- 未知票种保留原始 OCR 结果并转入人工复核，不直接丢弃。

### 5.2 确定重复

有发票代码的票据使用“用户 + 票种 + 发票代码 + 发票号码”作为唯一业务键。火车票使用“用户 + 电子客票号”作为唯一业务键；机票行程单使用“用户 + 电子客票号码”作为唯一业务键。其他票据只有在 OCR 提供该票种官方唯一号码时才建立确定重复键；缺少官方唯一号码时只能判为疑似重复，避免误拦。数据库唯一约束与应用层检查共同保证并发导入时不会漏拦。

确定重复票状态为“已拦截”，不得进入台账。界面展示已存在票据、首次导入时间和命中字段。

### 5.3 疑似重复

使用销售方或承运方、日期、含税金额、乘客、行程等归一化字段生成组合指纹并计算匹配分。疑似重复只进入人工复核，不自动拦截。阈值与命中原因必须可解释、可配置。

## 6. 状态模型

处理状态包括：

- `QUEUED`：等待 OCR。
- `OCR_PROCESSING`：正在调用 OCR。
- `REVIEW_REQUIRED`：存在低置信度、字段异常或疑似重复。
- `PASSED`：核验通过且无确定重复。
- `BLOCKED_DUPLICATE`：命中确定重复。
- `FAILED`：文件或外部服务导致处理失败。

人工修改字段会创建审计事件并重新运行规则，不直接篡改之前的 OCR 原始响应。

## 7. 数据模型

- `users`：账号、密码哈希、状态和时间戳。
- `ocr_credentials`：用户、加密 API Key、加密 Secret Key、验证状态和更新时间。
- `import_batches`：用户、批次编号、数量和处理汇总。
- `invoice_files`：用户、批次、文件名、MIME、大小、SHA-256 和受控存储标识。
- `invoices`：用户、票种、状态、代码、号码、日期、金额、税额、价税合计、交易主体和统一字段。
- `ocr_results`：发票、供应商、模型或接口版本、原始响应和字段置信度。
- `verification_issues`：发票、规则编号、严重级别、字段、原因和处理状态。
- `duplicate_matches`：当前票、目标票、匹配类型、分数、命中依据和处理结果。
- `audit_events`：用户、动作、对象、变更摘要、时间和请求标识。

业务表均包含 `user_id`。Repository 和 Service 两层都不得提供绕过用户范围的普通查询接口。

## 8. API 与安全

- Spring Security 负责认证与授权。
- 密码使用 BCrypt 哈希。
- JWT 通过 `HttpOnly`、`SameSite` Cookie 传递；生产环境启用 `Secure`。
- 修改状态的请求启用 CSRF 防护。
- OCR 凭据使用 AES-GCM 加密；加密主密钥只从服务端环境变量或密钥服务读取，不写入数据库或仓库。
- 凭据查询接口只返回“已配置”、掩码和最后验证时间，绝不返回 Secret 明文。
- API、下载、SSE、导出和 ERP 操作都校验当前用户范围。
- 日志不得记录密码、令牌、OCR Secret、Cookie 或完整外部响应。
- 上传接口限制大小、文件数量和允许格式，并验证实际 MIME。

核心 API 分组：

- `/api/auth/*`：注册、登录、刷新和退出。
- `/api/settings/ocr-credentials`：保存、测试、查询掩码状态和删除凭据。
- `/api/import-batches`：创建批次、上传、查询进度。
- `/api/invoices`：列表、详情、人工修正和状态处理。
- `/api/invoices/{id}/duplicates`：重复依据和目标票据。
- `/api/ledger`：台账查询和统计。
- `/api/exports`：CSV/Excel 导出。
- `/api/integrations/erp/*`：ERP 查询与推送。

## 9. 异常处理

- Paddle 超时、限流或 5xx 使用指数退避重试，最多 3 次。
- 凭据无效或权限不足不重试，提示用户更新设置。
- 文件损坏、超限、格式不支持或 MIME 不符在 OCR 前拒绝。
- 批次内每张票独立处理，单张失败不终止整个批次。
- 失败任务保留原文件、错误分类和请求标识，允许用户手动重试。
- 外部响应结构变化映射为可诊断错误，不把堆栈或敏感数据返回前端。
- 导出与 ERP 推送使用幂等请求标识，避免重复写入。

## 10. UI/UX

采用已确认的三栏核对工作台：

- 左栏：批次与待处理队列。
- 中栏：原票预览、缩放和翻页。
- 右栏：结构化字段、置信度、核验问题、重复依据和处理动作。

视觉方向采用石墨单色的高端浅色界面：

- 浅灰画布、悬浮白色面板、精细描边、柔和阴影和充足留白。
- 主操作使用近黑色；蓝色仅用于文字链接、键盘焦点和少量交互反馈。
- 选中项通过边框、层级和灰度区分，不使用大面积蓝底。
- 状态色缩小为圆点或极浅底色；红色仅表示确定错误或重复拦截。
- 每个视图最多一个实心主按钮。
- 使用系统字体栈、圆润控件和清晰的数字对齐。
- 支持键盘导航、可见焦点、语义标签和 WCAG AA 对比度。

当前环境没有可调用的 `huashu design` 工具，因此实现以用户确认的可视化稿和本节规范为准；若后续启用该工具，只允许细化视觉令牌，不得改变已确认的业务流程和交互结构。

## 11. 测试与验收

### 11.1 自动化测试

- JUnit：字段归一化、金额关系、精确查重、疑似重复评分和状态转换。
- WireMock：Paddle 成功、超时、限流、鉴权失败和异常响应。
- Testcontainers PostgreSQL：持久化、事务、唯一约束、并发查重和用户隔离。
- Vitest 与 Vue Testing Library：表单、队列、字段编辑、状态展示和错误反馈。
- Playwright：注册登录、录入凭据、批量上传、人工复核、重复拦截、台账和导出。
- 安全测试：跨用户 ID 访问、未授权文件访问、凭据泄漏和上传绕过。

### 11.2 基准样本

建立按票种分层的脱敏样本集，每个样本包含期望字段、异常标签和重复关系。指标计算规则固定到测试脚本，避免人工选择有利样本。OCR 服务自身不可用时，契约测试使用固定响应；真实准确率验收必须在配置有效 Paddle 凭据后运行。

### 11.3 完成标准

- 前后端可通过文档化命令启动。
- 数据库迁移可从空库完成。
- 用户可完成端到端主流程。
- 自动化测试通过。
- 基准样本达到第 1 节指标。
- API 文档、环境变量示例和部署说明完整。
- 仓库不包含真实凭据、原始敏感票据或生产密钥。
